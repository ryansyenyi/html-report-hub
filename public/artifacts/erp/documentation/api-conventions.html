API Conventions

ERP · internal REST conventions reference (illustrative, non-production endpoints)

Base URL & versioning

All endpoints are versioned under a path prefix. Breaking changes bump the version segment; additive changes (new optional fields) do not.

https://api.erp.example.internal/v1/<resource>

Resource naming

  • Collections are plural nouns: /purchase-orders, /vendors.
  • A single resource is addressed by id: /purchase-orders/{id}.
  • Nested sub-resources stay one level deep: /purchase-orders/{id}/line-items.

Request example

Creating a purchase order:

POST /v1/purchase-orders
Content-Type: application/json

{
  "vendorId": "vnd_8841",
  "currency": "USD",
  "lineItems": [
    { "sku": "SKU-1029", "quantity": 12, "unitPrice": "4.50" }
  ]
}

Response example

HTTP/1.1 201 Created
Content-Type: application/json

{
  "id": "po_5591",
  "status": "pending_approval",
  "vendorId": "vnd_8841",
  "total": "54.00",
  "createdAt": "2026-09-12T10:04:00Z"
}

Standard error shape

{
  "error": {
    "code": "validation_failed",
    "message": "lineItems[0].quantity must be greater than 0",
    "field": "lineItems[0].quantity"
  }
}

Common status codes

CodeMeaning
200Successful read or update
201Resource created
400Malformed request body
404Resource does not exist or is not visible to the caller
409Conflicting state transition (e.g. approving an already-cancelled order)
422Well-formed request that fails business validation

Pagination

List endpoints accept limit and cursor query parameters and return an opaque nextCursor in the response body when more results exist:

GET /v1/vendors?limit=20&cursor=eyJvZmZzZXQiOjIwfQ

{
  "items": [ ... ],
  "nextCursor": "eyJvZmZzZXQiOjQwfQ"
}
