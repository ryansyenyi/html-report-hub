Architecture — before and after

Same routes, same HTTP bytes, same gate order. The change is the shape of the caller that business code receives: three door-specific bags → one sealed Principal + Core-owned Access.

Before

Three authenticating middlewares, one overloaded projection, seven Actor copies.

After (Module 1)

Adapters mint; Core derives Access; ActorFor refuses before BeginTx — never falls back to System.

Request journey (every protected call)

Fail-closed on every auth path — no silent actor.System fallback (AGENTS.md rule 3 / ONP-14).

Sealed Principal variants

Read only through identity.Match. Zero / nil / typed-nil / embedding forgery → ErrNoPrincipal (ONP-01, ONP-08).

Worked examples

Concrete call paths — what code sees before vs after.

Before — mixed bag
// httpx.Principal carried everything
p := httpx.PrincipalFrom(ctx)
// who + capacity + CSRF + tenant hints
_ = p.AccountID
_ = p.CSRFToken          // session machinery
_ = p.Role               // authorization fact
actor.From(ctx)          // one of 7 local copies
After — split seam
p, ok := identity.From(ctx)     // Person only
access, ok := authz.AccessFrom(ctx)
// CSRF lives in session.State (private)
actor, err := authz.ActorFor(p, access)
// Person → Kind person|platform
// missing Access → refuse (not System)
Before — easy to confuse
// Delegate key set IsDelegate + TenantFrom
// Person session overwrote "who"
// Gates re-read string flags
if httpx.IsDelegate(ctx) { … }
if httpx.IsAdminKey(ctx) { … }
// tenantless delegate == admin
// (ADR-0025 accepted risk)
After — provenance explicit
// Person Principal, Channel=Delegated{Via}
// Key never becomes the actor
ActorFor → the person
// Via logged as fingerprint only
// X-Narya-Edge: public → 401
//   for any delegate key (TMS-223)
// DelegateUnscoped ≠ AdminKey
Delegation narrows, never grants (ONP-04 / D2). Module 3 will extend Via into a full chain (audience, grant, persisted delegating actor).
Before — wrong label
// DeviceAuth set key id = credential id
// with no tenant → looked like admin key
Kind:  "api_key"
Label: "key:admin/<credentialID>"
// credential id leaked into audit columns
// portal could read it back
After — ONP-15 only change
identity/device.Mint → Device Principal
ActorFor / actor.From arm:
Kind:  "device"
Label: "device:<uuid>"
// no backfill — nothing was persisted
// serial stays off the Principal (ONP-02)
This is the only intentional behaviour change in Module 1 (ONP-25). Everything else is parity.
Before — inferred admin
// Missing tenant ⇒ treat as admin
IsAdminKey := KeyID != "" && Tenant == ""
// easy to mis-classify a broken
// delegate assertion as admin
After — named authority
MatchKeyAuthority(p,
  onAdmin, onTenant,
  onDelegateUnscoped, onDelegateAsserted)
// RequireAdmin reads sealed authority
// static AUTH_TENANT_API_KEYS:
//   Core refuses boot; dms/BFF too (#460)
