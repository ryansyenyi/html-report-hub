Verdict

Module 3 moves persons, login identities, sessions and CSRF, password flows and signing keys out of Core and into a new identity-svc. Traefik ForwardAuth moves with them and mints a ≤30 s EdDSA assertion, and Core keeps every authorization decision (ADR-0119/0120, E3-02). What is on main today is the scaffolding: ADRs, the vendored guide, two behaviour-neutral Core preparations, an identity-svc with empty route tables, and a staging database. No request is served by identity-svc yet, and no user-visible behaviour has changed.

Architecture: before, now, after

The three views share one layout, so switching between them shows what moves. The browser contract, the Cloudflare Worker, the device plane, tenant API keys and every authorization decision in Core stay unchanged (E3-34, §8.10). What changes is who holds the credential and how Core learns who is calling: a signed assertion replaces a second session lookup.

Session lookups per protected request

2 → 1
ForwardAuth plus Core ResolveSession becomes a single token-hash lookup in identity-svc. Core verifies the signature locally against cached JWKS and re-reads the account fresh.

Assertion (ADR-0120)

X-Narya-Assertion: JWS, alg=EdDSA, typ=narya-assertion+jwt, kid in the header. Claims iss aud=core sub sid act? rst? name iat exp≤iat+30s. It carries no role, scope or tenant. Keys are ephemeral per pod, and only the public halves are stored.

Service-to-service trust (ADR-0124)

One SOPS bearer key per edge from S4 (AUTH_INTERNAL_API_KEYS, Principal kind Workload), with default-deny NetworkPolicy (:8081 accepts Traefik only). mTLS comes later at S11 / TMS-363 and is not on the flip path.

Suspension and session revocation use the same pattern. They are called pre-commit inside Core's transaction under a shared allowance of min(first+3s, deadline−1s), and a failure rolls back to a 503.

What can go wrong
1. identity-svc is down
2. A client forges X-Narya-Assertion
3. Role revoked while the assertion is live
4. Assertion replayed after 30 s
5. Unknown kid (pod rotated its key)
6. Delegate key sent without an assertion
Designed response
1. Traefik empty-body 500 → SPA outage probe
   /auth/me → outage screen, session kept
   (E3-19/E3-68; no errors middleware)
2. stripped at edge (E3-15, S1) + overwritten by
   authResponseHeaders + signature fails → 401
3. Core re-reads the account per request → 403
4. exp ≤ iat+30s, skew ≤5 s → uniform 401
5. capped unknown-kid JWKS refresh, 2 s pull
6. BFF refuses 401 without calling Core
