Platform System Design

Infra · high-level service topology (fictional architecture)

Components

  • Edge Gateway — terminates TLS, routes by hostname, applies rate limiting.
  • Auth Service — issues and verifies short-lived session tokens; stateless verification on every request.
  • Core API — the main application service; stateless, horizontally scaled behind the gateway.
  • Task Queue — background jobs (report generation, notifications) run asynchronously off the request path.
  • Primary DB — relational store for transactional data, single-writer with read replicas.
  • Object Store — durable blob storage for uploaded artifacts and generated exports.

Design notes

The Core API is intentionally stateless so it can scale horizontally without sticky sessions. Long-running work (report exports, batch notifications) is pushed onto the Task Queue rather than handled inline, keeping request latency predictable under load.

The Auth Service is decoupled from the Core API so token verification logic can evolve independently and be reused by other internal services without duplicating session handling.
